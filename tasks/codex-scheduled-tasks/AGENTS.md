# Codex 定时任务维护

仅在 Mac mini 执行。凭据、运行数据和原任务记忆不入 Git，不输出认证信息。迁移验证使用模拟数据、账号/模型只读预检和只读看板，不主动发起业务模型、通知、PR 或邮件标记。保留周期、统计窗口、项目、原会话、记忆及去重凭据。通知仅走 notify.py 和统一 webhook-delivery；不绕过发送账本。

- SigNoz 的 EOF、超时、连接中断和 HTTP 429/500/502/503/504 在同一只读查询和时间窗口内等待 10、30、60 秒，最多重试 3 次；证书校验、权限及不存在等永久错误不做无效重试。只有截断、明确的查询资源限制或 count/extract 不匹配才拆窗，网络错误禁止递归拆窗。异常必须保留脱敏分类、底层类型、尝试次数、窗口和适用的证书校验信息，写入状态及看板摘要；不得记录 API key、SQL、响应体或任意异常原文。采集失败不调用模型、不发送报告、不冒充零数据。

- SigNoz 可能省略 MEMORY_LIMIT_EXCEEDED 符号名，只在包装 HTTP 500 中返回 ClickHouse code: 241 和 memory limit 描述；两者同时匹配时按查询资源限制拆窗，不能误当成普通网络故障。最小窗口仍失败要在看板明确显示资源/结果限制，不冒充采集完成。

- HTTP trace 归因查询与主日志查询统一处理资源限制拆窗；仍无法恢复时记录失败窗口与脱敏分类。SigNoz 的部分完成产物必须明确 log_analysis_complete:true，提示词与宿主协议同步；若报告已发送但遗漏标记，只能核对原始日志、聚类闭合和已发送凭据后修复产物协议，不重复调用模型或推送。

- SigNoz 主日志和 HTTP 归因统一以 5 分钟初始窗口串行查询，每批最多 40 个 trace ID；保持全日覆盖和最后不足整窗的边界，不恢复大窗试探。资源限制继续拆窗，网络错误仅原窗重试。缩小窗口不得跳过 count/extract、唯一 ID 或时间边界校验。

- SigNoz 在模型启动前由宿主完成错误归一化、分组和计数；模型只读取 signoz-digest.json，禁止读取原始逐条日志及全量分组。每组最多 2 条受控脱敏代表信息，每类每天最多 20 组，摘要不超过 128 KiB；超出部分保留准确长尾计数。不同状态码、错误码和校验约束不可误并，未知消息仅保留指纹和安全元数据。聚合计数、原始唯一 ID 或时间范围校验失败不得进入模型。
